# WorkBuddy 核心用法详解：腾讯全场景 AI 智能体实战指南

传统 AI 聊天工具只负责"生成文字"，而 WorkBuddy 是腾讯云代码助手团队于 2026 年 3 月 9 日推出的**全场景职场 AI 智能体桌面工作台**——它能理解你的自然语言指令，在电脑上自主拆解任务、规划执行步骤、调用本地文件和外部服务，最终交付可直接验收的工作成果。简单说：**它不是在和你聊天，而是真的在帮你干活**。

上线首月月访问量 885 万，2026 年 6 月突破 2097 万，WorkBuddy 已成为国内 PC 端 AI 原生办公智能体市场第一。本文基于官方文档与社区实战资料，详解它的核心用法，并给出大量可直接照抄的指令示例。

<!--more-->

## 核心概念：四层架构

理解 WorkBuddy 的用法，先理解它的四层架构：

| 层级 | 组件 | 作用 |
|------|------|------|
| 执行层 | 桌面客户端 | 本地运行，读写本机文件、执行系统操作，数据不强制上云 |
| 遥控层 | 助理（Claw） | 把桌面客户端暴露为远程可控智能体，手机发消息即可派活 |
| 方法论层 | Skills 技能包 | 把 SOP、输出模板、业务规则打包成 `SKILL.md`，让 AI 按手册干活 |
| 连接层 | MCP 协议 | 连接腾讯地图、QQ 邮箱、腾讯文档等外部服务，无需编程 |

这四层组合起来就是：**桌面干活 + 手机指挥 + 技能约束 + 外部服务打通**。

## 安装与基础配置

### 系统要求

- **操作系统**：Windows 10/11 或 macOS 10.15+
- **存储空间**：约 150-180 MB
- **网络**：需要稳定网络连接

### 安装步骤

1. 访问 [WorkBuddy 官网](https://www.codebuddy.cn/work/) 下载对应版本（Windows 为 `WorkBuddySetup.exe`，macOS 为 `WorkBuddy.dmg`）
2. Windows 双击安装包按向导完成安装；macOS 拖拽到"应用程序"并在「系统设置 → 安全性与隐私」中允许打开
3. 使用腾讯账号登录（推荐企业微信或 QQ 账号，方便后续用 Claw 远程控制）
4. 首次使用需授权 WorkBuddy 访问本地文件夹（桌面、文档、下载等）

> **安全建议**：仅授权必要的文件夹（如桌面、文档），避免授予敏感数据目录的访问权限。任务默认在沙箱环境中执行，降低误操作风险。

### 模型选择

WorkBuddy 默认使用 **Auto 模型**，根据任务类型自动路由：简单问答走轻量快速模型，复杂推理走更强模型。国内版内置模型以腾讯混元为核心，可手动切换 DeepSeek、GLM、Kimi 等：

- **日常办公**：Auto / 混元（响应快、省积分）
- **复杂任务分析**：DeepSeek、GLM（推理能力强）
- **创意写作**：Kimi（文本生成质量高）

进阶用户还可以接入外部 API（DeepSeek 官方、Qwen 等），只需编辑本地模型配置文件，填入 `apiKey` 和 `baseUrl`。

## 核心用法一：自然语言指令

WorkBuddy 最核心的用法就是**用一句话下达任务**。基本流程是：

1. **下达指令**：用自然语言描述任务（越具体越好）
2. **确认计划**：AI 解析并展示执行步骤，确认后开始执行
3. **执行反馈**：在沙箱环境中运行，实时显示进度
4. **交付结果**：生成文件、图表或报告，可直接使用

### 典型指令示例

下面这些指令可以直接复制使用：

**Excel 数据处理**

```txt
把桌面"2026Q1销售数据"文件夹里所有Excel合并，生成柱状图和分析报告
```

**文档批量转换**

```txt
把D盘"周报"文件夹里所有Word转成PDF，并按日期重命名
```

**数据报表生成**

```txt
读取"业绩表.xlsx"，计算各部门环比，生成PPT并自动排版
```

**定时任务设置**

```txt
每天9点自动导出昨日订单数据，发送到企业微信群
```

**文件整理归档**

```txt
把下载文件夹里所有PDF按月份分类，移动到对应文件夹
```

### 指令撰写五技巧

想让 WorkBuddy 一次执行成功，指令里要包含这几个要素：

1. **指定路径**：明确文件或文件夹的完整路径，如 `桌面/2026Q1销售数据`
2. **明确格式**：说明输出格式（PDF、Excel、PPT 等）
3. **说明要求**：描述具体细节（图表类型、分析维度、合并方式）
4. **划定边界**：说明哪些文件要处理、哪些不能碰
5. **从简单开始**：先跑通小任务，再逐步加大复杂度，便于排查失败原因

## 核心用法二：Skills 技能包

Skills 是 WorkBuddy 最实用的扩展机制。本质是一个 `SKILL.md` 文件，写明执行某类任务时应遵循的方法论、输出格式和注意事项——等于给 AI 配备一本**工作手册**，让它按既定流程干活，而不是每次从头推理。

### 加载社区技能

WorkBuddy 兼容 OpenClaw 社区技能生态（`SKILL.md` 格式）。安装方法统一：

```bash
# 把技能文件夹（或 SKILL.md）放入技能目录
mkdir -p ~/.workbuddy/skills
cp -r /path/to/some-skill ~/.workbuddy/skills/

# 重启 WorkBuddy 后即可在技能列表里看到
```

社区中比较知名的技能包（数据截至 2026 年 8 月）：

- [mattpocock/skills](https://github.com/mattpocock/skills)（200k+ stars）：TypeScript 工程师日常开发工作流，覆盖类型系统分析、代码审查、API 设计评审、重构规划
- [op7418/Claude-to-IM-skill](https://github.com/op7418/Claude-to-IM-skill)（2.8k stars）：把 Claude Code / Codex 桥接到 Telegram、Discord、飞书，可在 IM 里直接对话编程 Agent

### 创建自己的技能

**方式一：AI 辅助生成**。在 WorkBuddy 对话框选择「创建技能」，用自然语言描述任务类型，WorkBuddy 自动生成 `SKILL.md` 草稿，确认后保存到技能目录。

**方式二：手动编写**。在 `~/.workbuddy/skills/` 下新建 `.md` 文件，结构参考：

```markdown
---
name: 周报生成专家
description: 根据本周工作记录生成结构化周报，遵循公司格式规范
---

## 适用场景
- 每周五下午生成周报
- 需要从工作日志中提取关键成果

## 执行步骤
1. 读取本周工作日志（~/.workbuddy/memory/工作日志.md）
2. 按「成果-问题-计划」三段式组织内容
3. 输出格式：标题 + 本周成果列表 + 下周计划列表

## 注意事项
- 数据必须来自实际日志，不得编造
- 使用公司规定的措辞风格
```

### 专家（Expert）功能

在 Skills 基础上更进一步：Skills 定义"怎么做"，专家定义"以什么角色做"。专家以「人设 + 方法论 + 工具链」组合赋予 WorkBuddy 特定领域身份（HR 专家、市场分析师、财务顾问等），配置后对话时会以该角色的思维框架处理任务。

## 核心用法三：Claw 远程控制

WorkBuddy 的「助理（Claw）」功能让你**在任意 IM 里发消息，远程驱动桌面端执行任务**，结果异步推送回来。出门开会也能用手机给电脑派活。

### 配置步骤

1. 打开 WorkBuddy，进入右上角**个人中心**
2. 点击**Claw 设置**
3. 选择要绑定的通讯工具：企业微信、微信、QQ、飞书、钉钉
4. 扫码完成授权绑定

### 使用方式

绑定后，在对应 IM 中找到 WorkBuddy 机器人，直接发指令：

```txt
帮我看一下家里电脑桌面上有没有"季度总结.docx"，有的话发给我
```

```txt
下午3点提醒我，并自动整理今天的会议纪要发到企业微信群
```

Claw 支持手机端文字、语音、图片和文件输入。典型场景：

- 外出时手机操控电脑自动完成报表
- 家里远程处理公司文件
- 随时随地启动自动化任务

## 核心用法四：MCP 连接器

MCP（Model Control Protocol）是 WorkBuddy 与外部服务之间的标准化对接通道。通过 MCP，WorkBuddy 不再是"生成文字"的 AI，而是能**直接操作第三方服务的智能体**。

### 内置连接器

WorkBuddy 预装了一批主流连接器：

- **QQ 邮箱**：收发邮件、自动分类、起草回复
- **腾讯文档**：读写、协作、格式转换
- **腾讯地图**：路线规划、地点搜索、周边推荐
- **有道云笔记**：笔记读写、标签管理
- **美团**：团购、外卖等生活服务（配合官方 Skills）
- **GitHub / Jira / Notion**：开发者与项目管理场景

### 配置方法

```
WorkBuddy 设置 → 连接器 → 添加服务
```

选择对应服务，按提示完成 OAuth 授权（首次需登录对应账号），完成后 WorkBuddy 就能直接调用该服务能力，无需任何编程。

### 自定义 MCP 服务器

WorkBuddy 支持接入符合 MCP 协议规范的第三方服务器，在设置里填入 MCP 服务器地址即可。社区 MCP 服务器列表可参考 GitHub 上的 `awesome-mcp-servers` 汇总。

> **Skills vs MCP 怎么选**：Skills 更简单——只是一个 Markdown 文件，零门槛；MCP 需要对应服务有 MCP 服务端支持并完成 OAuth 授权，适合有具体外部服务接入需求的场景。建议先把 Skills 用熟，再按需探索 MCP。

## 核心用法五：定时任务（Automation）

设置重复性任务，让 WorkBuddy 自动定期执行，适合"每天早上自动跑"这类固定动作：

```txt
每天早上9点，读取销售系统导出的昨日数据，生成日报发到企业微信群
```

```txt
每周五下午5点，整理本周所有会议纪要，汇总成一份周报保存到桌面
```

```txt
每月1号，把上个月的发票PDF按供应商分类归档到"财务/发票/2026-07"文件夹
```

配合 Claw 和 MCP，定时任务还能联动外部服务：定时导出 → 自动发送 → 归档，形成完整自动化链路。

## 核心用法六：Teams 多智能体

WorkBuddy 的 **Teams 功能**支持多个 Agent 并行处理不同子任务，由一个 lead agent 协调。你只需要提出一个复杂任务，它自动决定要不要拆、拆几个、谁验证谁：

```txt
帮我准备下周的产品发布会：Agent A 收集竞品资料，Agent B 整理市场数据，
Agent C 起草演讲稿，最后汇总成一份完整的发布会方案
```

对用户来说无需理解 sub-agent 的原理，复杂工程概念被封装在产品里了。

## 实战案例：一条指令完成数据周报

下面演示一个完整的实战流程。假设每周一你需要把上周销售数据做成周报：

```txt
① 读取"桌面/销售数据/上周销售明细.xlsx"
② 按产品线汇总销售额，计算环比增幅
③ 生成一张柱状图 + 一份分析报告（指出增长最快和最慢的产品线）
④ 输出为 "第31周销售周报.docx" 保存到桌面
⑤ 把报告发送到企业微信群
```

WorkBuddy 会依次执行：解析数据 → 计算汇总 → 调用 MCP 生成图与文档 → 通过 Claw 发送到企微群。整个过程一条指令完成，这正是指令 + Skills + MCP + Claw 四层能力叠加的效果。

## 常见问题 FAQ

**Q: WorkBuddy 和 QQ 小龙虾有什么区别？**
A: 两者定位不同。WorkBuddy 面向办公场景，独立客户端，支持多步骤复杂任务和多种 IM 远程控制；QQ 小龙虾集成在 QQ 中，偏生活场景的轻量任务。

**Q: Credits 是什么？怎么省着用？**
A: 新用户赠送 5000 Credits，复杂任务消耗较多。省用技巧：日常任务用 Auto/混元，复杂分析切换 DeepSeek 等强模型时合理规划，批量任务分批执行。

**Q: 提示权限拒绝怎么办？**
A: 重新授权文件夹访问权限。WorkBuddy 设置中检查桌面、文档、下载等目录是否被允许访问。

**Q: 任务执行失败如何排查？**
A: 先检查指令是否清晰（路径、格式、要求三要素），从简单子任务开始验证，再逐步组合。WorkBuddy 会展示执行日志，可据此定位失败的步骤。

**Q: Skills 目录在哪里？换机器怎么迁移？**
A: 国内版技能目录为 `~/.workbuddy/`（海外版 `~/.workbuddy-ai/`）。可将 skills、memory、对话记录等目录整体复制到新机器，或用社区的 workbuddy-asset-migration 技能自动迁移。

**Q: 数据会上传到云端吗？**
A: WorkBuddy 桌面客户端本地执行，数据不强制上云；但通过 IM（Claw）远程派发任务时，任务描述和产出文件会经过 IM 中转，企业敏感数据需注意这一风险。

## 总结

WorkBuddy 的核心用法可以归纳为一条主线：**用自然语言下指令，靠 Skills 约束方法论，借 MCP 打通外部服务，用 Claw 实现远程调度，用 Automation 固化重复劳动**。

- 新手：装好客户端，从"一句话指令"开始（Excel 合并、批量转换、文件归档）
- 进阶：编写/加载 Skills，配置 MCP 连接器提升自动化深度
- 高阶：绑定 Claw 远程指挥 + 定时任务 + Teams 多智能体，把个人工作流升级为"AI 团队"

在一个 Agent 时代，WorkBuddy 走的是与其他终端型 Agent（Claude Code、Codex）相反的 **messaging-first** 路线：用户不离开 IM，成品直接推到聊天里。如果你也想要一个"能办事"而非"能聊天"的 AI 同事，从上面任何一个指令示例开始试起来就好。
